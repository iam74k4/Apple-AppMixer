# デモ動画

AstLog（astlog.dev）の AppMixer のページに載せるデモ動画の版下と、書き出しの道具。

```bash
make demo-video
# または
marketing/demo/render.sh
```

`marketing/demo/build/appmixer-demo.mp4` に、1440×900（16:10）・30fps・H.264・音なしで出る。
長さは 15.2 秒（455 コマ）。

## アプリの実物の収録ではない

スクリーンショットと同じ部品（`marketing/screenshots/app.js` の `popover`）で組んだ
ポップオーバーを、台本（`video.js`）どおりに動かした**再現**。ポインタと指の動きも、
台本どおりに入れたもの。載せるページの代替テキストにも、そう書く。

- 実物を撮らないのは、スクリーンショットと同じ理由（撮るたびに同じ状態を作れる。
  通話中のダッキングのような状態も確実に出せる）と、実際の画面（壁紙・ほかのアプリの
  ウインドウ・本物のメニューバー・通知）を写さないため
- 見た目も数値も実際のアプリに合わせ、実際に存在しない機能や表示は載せない
  （`marketing/screenshots/README.md` の「画面はアプリと同じ見た目で組んでいる」）
- App Store の App プレビューには使わない。あちらはアプリそのものの画面収録だけが
  認められている（審査ガイドライン 2.3.4）

## 台本

1 場面に 1 機能。見れば何の機能か分かる順に並べている。秒は台本（`video.js` の `model(t)`）の時刻で、
書き出すのは `START`（1.62 秒）から。動画の秒は、ここから 1.62 を引いたもの。

| 秒 | 場面 | 見せる機能 |
|---|---|---|
| 0.3 – 1.4 | メニューバーのアイコンを押して、ポップオーバーを開く（台本にだけある。書き出さない） | — |
| 1.7 – 4.4 | Google Chrome のつまみを引いて、100% から 30% へ | アプリごとの音量 |
| 4.5 – 6.3 | システム音のミュートボタンを押す | ミュート |
| 6.4 – 9.2 | FaceTime の通話が始まり、ほかの音が自動で下がる。終わると戻る | 通話中の自動ダッキング |
| 9.1 – 11.7 | ミュージックの出力先のメニューから AirPods Pro を選ぶ | アプリごとの出力先 |
| 12.0 – 16.8 | ミュージックのメーターの上のつまみを左へ大きく引き、ポインタを離して、青くなったつまみを見せる | 左右バランス |

- **開いたところから書き出す。** AstLog の作品のページは、動画の 0.1 秒目を表紙（再生の前に出る絵）にする。
  アイコンを押すところから書き出すと、表紙が何も無い暗い画面になった（2026-11-11 のレビュー）。
  メニューバーのアイコンは開いている間の選択の角丸で描くので、メニューバーから開いたことは表紙でも分かる
- **置き場所は実物と同じ。** `MenuBarExtra`（`.window`）と App Store の画像と同じく、メニューバーのアイコンの真下に開き、
  画面の右端に収まるよう左へ押し戻す（`marketing/screenshots/app.js` の `layoutSide` と同じ式。出力先のメニューも同じく
  画面の内側へ押し戻す）。倍率は、FaceTime の行と帯が増えても右下の図に重ならない 1.5（前は 1.75 で、図を避けて
  アイコンの左へずらしていた）
- **区切りのつまみは細い**（3pt）。はっきり分かるところ（-0.6）まで寄せ、引いたあとはポインタをどけて、最後に 1.6 秒見せる

決まり（作者のアプリの宣伝用の動画で共通。2026-11-11）:

- 16:10・1440×900・H.264 の MP4。音は入れない。AstLog が受け取る動画は 10MB まで
- 背景は全アプリ共通の絵（真っ黒の無地 `#000000` と、描いたメニューバー。
  `marketing/screenshots/README.md` の「背景」）。実際の画面は写さない
- 字幕を焼き込まない。説明は、載せるページの文と代替テキストに書く
- 操作は図で見せる。右下のトラックパッドの図に指の位置を出し（白い丸に緑 `#30D158` の縁。
  押した瞬間と押している間は緑で塗る）、画面には描いたポインタと、押した位置の輪を重ねる。
  図の位置と大きさは全アプリで同じ（1440×900 の中で 320×213、右から 37・下から 34）
- 自動で起きる機能（ここではダッキング）の間は、図から指を離す。人が操作して
  いないことが分かるように
- 同じ操作を繰り返さない

## 台本を直す

`video.js` を直す。

- `model(t)` が、その時刻の画面の状態を返す（形は `marketing/screenshots/shots.js` の
  `popover` と同じ）。アプリが実際にその状況で出す表示だけを書く（決まりは `shots.js` の先頭）
- `moves` がポインタの道筋、`presses` が押したまま動かす区間、`clicks` が押した瞬間、
  `touching` が指が図に触れている区間。`START` から `END` までを書き出す（秒）
- 動きは渡された秒だけから決める。乱数や実際の時計を使うと、撮り直すたびに違う動画になる

手元で見るときは、`render.sh` を一度動かして部品と背景を作ってから、`video.html?mode=video&lang=ja`
を Chrome で開き（ウインドウは 1440×900）、コンソールで `renderAt(7.5)` のように秒を渡す（動画の秒。台本の秒は `START` を足したもの）。

直したら `render.sh` で作り直し、コマを並べて確かめる。全部のコマが `build/frames/` に
PNG で残る（`f00225.png` が 7.5 秒）。見るところは、背景が切れたコマが無いこと、
ポインタが部品の上に乗っていること、図の指が操作と合っていること。

アプリの画面（レイアウト・文言）を変えたときは、`marketing/screenshots/` の `app.js` と
`styles.css` を直す。動画は同じ部品を読むので、作り直すだけで合う。

## ファイル

| ファイル | 役割 |
|---|---|
| `video.html` | 版下（1440×900）。背景の上にポップオーバー・ポインタ・右下の図を重ねる |
| `video.js` | 台本。`window.renderAt(秒)` が、その時刻の 1 コマを組む |
| `render-frames.mjs` | Chrome のヘッドレスを 1 回だけ起動して、1 コマずつ PNG に撮る（npm の依存なし） |
| `render.sh` | 部品 → 背景 → コマ → MP4 を通しで動かす |
| `scripts/make-backdrop.swift` | 共通の背景（真っ黒の無地とメニューバー）を PNG に描く |
| `scripts/vidtool.swift` | 連番のコマを H.264 の MP4 にする（`encode`） |

`scripts/` の 2 つは、作者のほかのアプリの宣伝の素材と共通の道具の写し。見た目を全アプリで
そろえるための道具なので、色・寸法・文字をこのリポジトリだけで変えない。`vidtool.swift` の
`patch` と `concat` は、実物の画面を収録するアプリ用で、ここでは使わない。

`build/` は生成物のため Git に入れない。

必要なもの: Google Chrome、Swift（Xcode の Command Line Tools）、Node.js 22 以降
（`render-frames.mjs` が組み込みの WebSocket を使う）、アイコンを借りるアプリ
（Google Chrome・FaceTime・ミュージック）。
