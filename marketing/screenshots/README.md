# App Store のスクリーンショット

Mac App Store の製品ページに載せるスクリーンショット（日本語・英語 各 6 枚）の版下と、
書き出しの道具。

```bash
make screenshots
# または
marketing/screenshots/render.sh                      # 全部
marketing/screenshots/render.sh 02-auto-ducking ja   # 1 枚だけ
```

`marketing/screenshots/build/<ja|en>/*.png` に 2880×1800（16:10、アルファ無し）で出る。
ファイル名の番号順が App Store での並び順。

## 構成と狙い

買う前に試せない（体験版が無い）ため、スクリーンショットだけで「何ができて、
自分の困りごとが消えるのか」が分かることを目標にしている。1 枚 1 メッセージ。

| # | ファイル | 伝えること |
|---|---|---|
| 1 | `01-per-app-volume` | 何のアプリか。動画 30%・音楽 80%・システム音（通知音）ミュートという具体的な使い方 |
| 2 | `02-auto-ducking` | 通話が始まると他の音が自動で下がる |
| 3 | `03-per-device-memory` | イヤホンとスピーカーで別々の音量を覚える（2 つの状態を並べる） |
| 4 | `04-per-app-output` | アプリごとに出力先を選べる（出力先メニューを開いた状態） |
| 5 | `05-balance` | アプリごとの左右バランス（メーターの上の区切りのつまみ） |
| 6 | `06-features` | 機能一覧と、買い切り・データ収集なし・録音送信なし・動作要件 |

一覧の 1 枚目は検索結果や製品ページの最初に出るため、ここだけで用途が伝わるように
している。

## 背景

背景は、作者のアプリ（Nonet・AppMixer・SaifuLog など）の宣伝用の絵と動画で共通の
1 つにそろえている（2026-11-11）。アプリごとに背景が違うと、AstLog（astlog.dev）に
並べたときに見た目がばらつくため。決まりの要点:

- 実際の画面（macOS の壁紙・ほかのアプリのウインドウ・本物のメニューバー・通知）は
  写さない
- 地は墨の無地 `#222226`。グラデーションも飾りも持たない
- メニューバーは描いたもの。帯は `#1A1A1D`、その下に白 6% の細い線。右側に、右から
  日付・コントロールセンター・Wi-Fi・電池（100%）・アプリのアイコンを並べ、左側には
  何も描かない。日付は「11月7日(土) 9:41」（英語の絵は同じ日の「Sat Nov 7 9:41 AM」）
- 色はアプリごとに変えない。アプリごとに変えてよいのは差し色だけ（AppMixer は
  アプリのアクセントと同じ `#0A84FF`）

共通の背景の絵そのものは `scripts/make-backdrop.swift` が描く（デモ動画が敷く。
`marketing/demo/README.md`）。
スクリーンショットは、上の色と日付を `styles.css` の `.wallpaper` と `app.js` の
`menubar` に書いてある。**合わせてあるのは地・帯・線の色と、日付・電池だけ。**
文言の位置、メニューバーの帯の高さとアイコンの大きさ、ポップオーバーの位置は
App Store 用に組んだままで、共通の配置（左に小見出し・見出し・説明・箇条、右に
アプリの画面を、全アプリで同じ位置と大きさに置く）にはまだそろえていない。

以前は紺のグラデーションの地で、ポップオーバーの後ろに弱い青い光を置いていた。
その前は音を出しているアプリのウインドウを下に敷いていたが、縮小表示では情報が
多すぎて読めなかった。

## 画面はアプリと同じ見た目で組んでいる

アプリ本体の画面は HTML で再現している（実機の画面を毎回撮り直さなくて済むように、
また「音量を変えた状態」を確実に作れるように）。**見た目も数値も実際のアプリに
合わせてあり、実際に存在しない機能や表示は載せない**（審査ガイドライン 2.3.3）。

- レイアウトの値は `ContentView` / `AppRowView` の padding・フォントサイズをそのまま
  写している。つまみ 18×14pt、トラック 4pt は macOS 26 の実機から測った。行の高さは
  65.5pt（メーターとバランスのつまみの箱が 10pt）
- 状態の決まり（並び順、コントロールが見える条件、メーターの長さ、ダッキング中の表示）
  は `shots.js` の先頭に書いた。状態を足すときは、アプリが実際にそう表示するかを確かめる
- 言語ごとに、その言語の Mac で実際に出る表示にする。AppMixer 自身の文言は
  `bundle/<言語>.lproj/Localizable.strings` と同じもの（`app.js` の `UI`）、
  アプリ名とデバイス名は macOS が返す名前（英語の Mac では「ミュージック」ではなく
  「Music」、「MacBook Air のスピーカー」ではなく「MacBook Air Speakers」）

アプリ側のレイアウトや文言を変えたら、`app.js` / `styles.css` も合わせて直すこと。

## ファイル

| ファイル | 役割 |
|---|---|
| `shots.js` | 1 枚ごとの画面の状態と文言（日本語・英語） |
| `app.js` | 状態からポップオーバー・メニューバー・背景・文字組みを組み立てる |
| `styles.css` | 見た目（1440×900 で組み、2 倍で書き出す） |
| `index.html` | 版下。`?shot=<id>&lang=<ja\|en>` で 1 枚を選ぶ |
| `export_assets.swift` | SF Symbols とアプリアイコン（「システム音」の機種アイコンを含む）を PNG に書き出す |
| `assets.sh` | 部品（上の PNG と、フッターに出す版）を `build/` に作る |
| `render.sh` | 部品を作り、Chrome のヘッドレスで全枚数を書き出す |

`build/` は生成物のため Git に入れない。他社アプリのアイコン（Chrome・Discord など）は
この Mac にインストールされているものから毎回取り出す。

デモ動画（`marketing/demo/`）も、ここの部品とポップオーバー（`app.js`・`styles.css`・
`shots.js` の `APP` / `DEVICE`）をそのまま使う。`app.js` は `?mode=video` のとき、
配置をせずに部品だけを渡す。ここを直したら、動画も作り直して確かめること。

必要なもの: Google Chrome、Swift（Xcode の Command Line Tools）、`shots.js` で
アイコンを使っているアプリ（Google Chrome・FaceTime・ミュージック）。

手元で確かめるときは、`render.sh` を一度実行して部品を作ってから `index.html` を
Chrome で開き、ウインドウを 1440×900 にする。

## App Store Connect へ差し替える

リリース（`main` へのマージ）のたびに、release.yml の `screenshots` ジョブが
`make screenshots` で作り直し、`scripts/asc.py screenshots` でその版の日本語・
英語（全地域）の枠へ入れ替える。手でドラッグする必要は無い。

- 配信中のバージョンの絵は変えられないため、入れる先はこれから出す版。
  版が無ければ submit と同じ要領で作る
- 提出（submit）はこのジョブの成功を待つ。入れ替えの途中は版が審査に出せる
  状態ではないため。失敗したら直してから、release.yml の失敗したジョブを
  再実行する
- 手で入れたいときは、`build/ja` の 6 枚を日本語へ、`build/en` の 6 枚を
  英語（アメリカ）と英語（カナダ）へ入れる
